The upload did not generate the tariff claim.

## What tariff misclassification means

General meaning:

```text
The utility or billing system applies a rate schedule or service class that does
not match the premise's approved service characteristics.
```

Possible effects include:

```text
wrong fixed charge
wrong kWh delivery factor
wrong demand-billing treatment
wrong voltage class
wrong rider
wrong ratchet treatment
```

It is a real audit category.

## What is required to prove it

At minimum:

```text
current official utility tariff
current rate code or schedule assigned to the ESI ID
utility territory
service voltage
metering configuration
billing demand
historical demand where ratchets apply
service-class eligibility
bill calculation under current class
bill calculation under alleged correct class
effective dates
source-backed deterministic comparison
```

A retail bill that only shows an aggregate TDU delivery charge is generally insufficient by itself.

## Specific TXU claim verdict

For this uploaded bill:

```text
Plausible category of issue: yes

Specific monthly overcharge proven: no

```

Do not use the label:

```text
Demand-Adjusted Industrial Rate
```

unless the exact current official tariff or rate-code source uses or supports that terminology.

## Opportunity provenance states

Add an explicit customer-facing trust state.

Suggested:

```text
evidence_backed
needs_evidence
manual_note
demo_example
deprecated
```

Derive or store it deliberately.

### Evidence-backed

Requires:

```text
source record
evidence reference
rule key and version
deterministic calculation inputs
deterministic calculation result
current source date when required
```

### Manual note

May be useful internally but must not present:

```text
confirmed savings
confirmed overcharge
verified classification
```

### Demo example

Must show a persistent sample badge and remain separate from real uploaded records.

## Monetary-claim gate

Do not show estimated savings as customer-facing truth unless:

```text
calculation_result exists
calculation_version exists
material assumptions are displayed
source evidence is linked
```

For unsupported manual records:

```text
hide the dollar amount
or label it as an unverified internal estimate
```

## Context on finding cards

Every finding card should show:

```text
source document
expense account
service location
account last four when authorized
meter or service identifier when authorized
generated by
evidence count
rule version
last evaluated
```

The vendor name alone is not enough.

## Prevent vendor-level contamination

A newly uploaded TXU bill should not visually inherit an unrelated TXU opportunity without context.

Use:

```text
document-scoped analysis
account-scoped opportunities
vendor-wide other findings
```

Separate sections:

```text
Findings from this bill
Other TXU findings in this workspace
```

The second section must identify its account and location.

## Demo workspace policy

The incident occurred in a seeded workspace:

```text
Apex Logistics Group
```

Add a visible banner when a workspace contains sample data:

```text
Sample workspace
This workspace contains demonstration records that are not based on your uploaded documents.
```

When a user uploads a real bill to a sample workspace, warn:

```text
This bill will be stored beside sample records. Create a clean pilot workspace
for customer testing.
```

Do not block the user, but prevent provenance confusion.

## Existing data remediation

Create an owner-only report that lists customer-visible opportunities with:

```text
generated_by = manual
evidence_count = 0
nonzero monetary claim
no calculation result
```

Do not silently delete them.

Provide actions:

```text
Mark demo
Convert to manual note
Attach evidence
Deprecate
Remove from customer view
```

For the specific TXU seeded record, mark it as demo or remove it from customer view after owner review.

## Tariff-rule implementation

Do not create a tariff-misclassification rule from a single aggregate delivery charge.

A valid rule must fail closed when any required dimension is missing.

Output when missing:

```text
Tariff review may be worthwhile
Current bill does not identify the assigned delivery rate schedule.
Obtain the official rate code and current tariff before drawing a conclusion.
```

## Tests

Add cases:

- Manual finding with no evidence
- Manual finding with unsupported dollar claim
- Demo finding
- Evidence-backed deterministic finding
- Uploaded document with no finding
- Same vendor, different account
- Same vendor, different meter
- Missing tariff rate code

Require:

```text
The uploaded bill no longer appears to have generated Meter #4491 finding
No zero-evidence finding is styled as proven
No unsupported tariff savings are shown
Demo records are visibly marked
Document/account/vendor scopes are distinct
```
